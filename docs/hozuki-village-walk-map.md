# 鬼灯村：添付配置からの歩行マップ hv-1

## 実装範囲

改善ブランチ `improve/hozuki-village`、main基点 `74234d9d038a9c0b65fdda39fd4fe2a69e5abdc8`。入口は `hozuki-village.html`。村名は鬼灯村。添付21×18マス、32px、672×576を維持し、新規原画は生成しない。

ユーザーの4ファイルを assets/maps/hozuki-village-v1/{layout.json,collision.json,ground.png,reference.png} として内容を変更せず保存。manifestにSHA-256、サイズ、出典の役割を記録。207不可セル、出現(10,17)、9入口/出口を厳密に照合し、不一致は起動失敗として扱う。171通行可セルがすべて出現点から接続する。

地面は添付ground.png、物体は採用済みの独立チップ。SMRenderの接地下辺・補間足元の共通深度順で描画する。元の合成PNGを物体の深度レイヤーへ使わない。地面＋チップのみの合成は添付reference.pngとRGBA全画素一致。

SMWalkで上下左右のセル単位移動、1歩144ms、タップ経路探索。元の明示占有・手動通行指定を維持する。すべての判定・経路は同じモデルを使う。セーブやエディタの保存キーへ書き込まない。

## カメラと緋月

ユーザー指定「フィールドマップでの緋月の大きさ」を採用。原本 `assets/characters/hizuki/field-sd-v1/walk-atlas-32.png` をそのまま使用し、エディタの緋月と同じblob `1edd462d006e9f71e4800a3ba746bdde1e4915c0` であることを確認した。

main基点game.jsのfield外側1.2倍、landscape.jsのzoom1.4、標準preset far=.34/near=1.30/gamma=1.85、カメラ足元anchor354/543から基準倍率を求める。通常画面の倍率は `1.2 * 1.4 * (.34 + .96 * (354/543)^1.85) * max(viewportWidth,viewportHeight)/768`。本編の768px canvas・object-fit:cover相当の画面サイズに合わせる。村全体を収める倍率を通常カメラへ使わない。

本編同様neutral列のalpha>=32から方向別の可視boundsを取り、一つの変換を全歩行フレームへ使う。SDを28pxへ正規化し、村では可視全体をセル中央へ配置する。画素の微小alphaを32px枠全体として測り、体を小さくすることを避ける。歩行frame→atlas列の対応も本編と同じneutral/足上げへ変換する。画像自体は変更しない。

通常は緋月を追従。「全景」は別の画面内フィット、そこでもタップできる。「緋月へ」は通常倍率へ戻る。端のカメラは地図外へ出ない範囲へ制限し、描画とタップは同じカメラ変換を使う。

## 操作と制限

スマホ用十字キー、pointer capture・pointercancel・lostcapture・blur・visibilityで入力を解除し、長押し選択や自走を防ぐ。設定を開くと歩行は停止する。初期ロード完了まで操作無効、失敗時は再読込の案内を出す。

「調べる」は現在の入口セルまたは手前から入口を向いた位置を認識する。屋内・フィールド遷移、NPC、旧本編のイベントは未接続。既存の鬼灯の里は旧座標・イベントとセーブを持つため、今回の新座標へ自動置換しない。独立ページで歩行を確認してから、本編接続の対象・遷移先・イベント位置を確定する。本編未統合を完了扱いしない。
