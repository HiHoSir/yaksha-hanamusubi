# 二重フィールドマップ構成 v1 (2026-10-09)

## 確定した設計
- **新大陸フィールド**: 80×80 cells, 32px/cell, id `new_continent`. 現行の `js/world.js`、7地点、イベント、セーブ位置移行を保持。
- **全体フィールド**: 256×256 cells, 32px/cell in game; id `whole_world`. 原作の256分割解析は**内部の位置・地理関係の検証資料**であり、公開ゲームへ画像・ROMタイル・分類結果の丸写しは行わない。
- ROM復元画像4096×4096を256分割した16pxは解析画像のサンプリング幅。ゲームの1セル描画幅32pxとは独立。
- 描画時のタイル窓は周囲数十マスのみとし、256×256の全地形を毎フレーム描画しない。背景・オブジェクト・衝突・イベント・橋は別レイヤーとする。
- 領域遷移: 新大陸で船出イベント達成 → 全体世界の検証済み港セルへ遷移。帰還可能なイベントを後から追加。港セルは現段階で**未確定**。仮の座標を公開進行イベントに入れない。
- 旧セーブにはmapIdがないため、読み込み時の既定値は `new_continent` とする。既存座標や `migratePosition` を壊さないようセーブ側の本実装は後工程。

## 実装済み
`js/world-map-registry.js`：既存ゲームから切り離したオプトイン管理API。256×256行列の寸法・地形値を検証し、原作由来データの使用を意図的に拒否。地形参照・移動判定と、船出フラグを要求する遷移の原型を実装。

### 注意
- まだ `index.html` に読み込ませていないため、**実ゲームでの世界地図切替は未接続**。
- 検証用 `map256_analysis_package(1).zip` は非公開解析資料。公開レポジトリへ登録しない。
- 元の256×256分類は浅瀬/川の推定を含み、衝突判定やイベント地形として未検証。公開用の独立制作マップが完成するまで直接使用しない。
- 本作業では `js/world.js`、`js/game.js`、`index.html`、セーブ処理、既存7地点を変更しない。
