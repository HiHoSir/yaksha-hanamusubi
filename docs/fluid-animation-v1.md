# 流動素材：最小2コマ

対象は `improve/interior-map-editor-32px`。ユーザーの「水とか川も含めて、流動的なものは最小限のコマ数でアニメーション」という指示を適用。原則2コマ、海・川・池・滝は360msごとに交互表示、既存の火は180msを維持する。岸、石囲い、器具、地形高さ、接地、占有、衝突、入口は固定。

## 素材

すべて既存の採用画像の加工。新規画像生成なし。元画像は保持する。

| 素材 | 1コマ | 2コマのPNG | 処理 |
| --- | --- | --- | --- |
| フィールドの海・川 | 64×64 | 128×64 | 水面の模様を2px/1pxずらす。岸の形状は既存モデルのまま |
| 汎用水面 | 32×32 | 64×32 | 既存村水面を加工。両コマで上下左右の反復端を維持 |
| 村・室内の川 | 47形、各32×32 | 256×384、上192pxが1コマ目 | 既存47形の岸は固定、水面のみ加工。自動接続は既存SMAutotileを使用 |
| 宿の庭池 | 64×64 | 128×64 | 石囲いとRGBA形状は固定、明示した水面領域のみ変える |
| 既存の滝 | 80×96 | 160×96 | 明示した落水領域だけを縦方向にずらす。周囲の岩・草を維持 |

出力先は `assets/animation/fluid-v1/`。`manifest.json`にフレーム寸法・配置・間隔、`*-water-mask.png`に視覚加工範囲を保存。視覚マスクを衝突に流用しない。再構築は `python3 tools/build-fluid-animation.py`。`review.gif` は2コマの確認画像で、ゲームではPNGアトラスを使う。

## 描画への接続

- 室内エディタ：池2×2を一式のまま2コマ化。新しい床「水面・2コマ」「川・自動接続・2コマ」を追加。水の床セルは通行不可。隣接する川・水面で接続を計算する。火とは別の位相で水を360msごとに更新、非表示時と静止素材しかない場合は更新しない。
- 村エディタ：既存の自動接続川が2コマ化。歩行を止めていても360msごとに更新。PNG出力は1コマ目で固定し、編集JSONには既存のID・占有を保存する。
- 村のゲーム描画：採用済みの地面PNGを維持し、水と橋だけを描き足してから家具・NPC・緋月を描く。橋の不透明部分は固定、隙間の水は動く。水→橋の順を配置順から独立させる。
- フィールドのゲーム描画：海・川の水面だけを小さな64pxの2枚から選ぶ。既存の地形キャッシュの水を使い続ける経路を外し、水面を現在の位相でサンプリングする。海の外周と地図内で位相を共有。滝の独立物体も同じ2コマを参照する。
- 地面全体の2枚複製・毎コマの再生成は行わない。地形チャンク数の上限64と、元の移動・段差・岸モデルを維持する。

フィールドの旧デバッグ用平面合成画像や一枚背景には自動で動きを焼き込まない。現行の高低差フィールド、現行村、両エディタの表示を対象とする。静止画像の形式ではアニメーションを保持できないため、PNG書き出しとJSON＋PNGアトラスの用途を区別する。

## 検査

`node qa/fluid-animation.cjs`：5つの2コマアトラスの寸法・画素差・固定アルファ、石・岸の不変、47形の両コマで各2048の接続辺、橋の不透明部分と描画順、静止PNG、JSON・判定・橋の経路の不変、室内の川接続、非表示時停止、水360ms、フィールド用Canvasが2枚だけで再利用されることを確認。

実際の `YK_LANDSCAPE.drawQuarter` と `YK_HOZUKI.draw` をローカルCanvasへ描き、0/360msで表示が変わり、地形・村の経路データとチャンク数が変わらないことを確認。ブラウザ全体の既存統合テストはjsdom依存が現環境にないため実行できず、実モジュールを直接ロードするCanvas検査で補った。実ブラウザ操作・Safari実機は未検査。

既存の室内・火・家具・階段・村の川と橋・NPC・高低差・キャッシュの検査も実行。プレビューのゲーム表示はBETA16.1.46へ更新し、HTMLと独立したgame.jsの識別子、index.html内の全ゲーム用キャッシュ版を一致させた。本編mainは未変更。GitHubとPagesは納品時に実体を別途確認する。
