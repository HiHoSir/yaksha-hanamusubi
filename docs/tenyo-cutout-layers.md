# 天妖の社：周辺の森のまとまりと奥行き（BETA 16.1.19）

原画1536×1024 WebPと48×32の通行JSONを維持する。BETA16.1.18の原画y=224による一括分割は使用せず、社の上側・左右の森を8つのまとまりに分けて人物と同じ足元順で描く。南側に残る森は固定の前景。

## 元画素を維持した分割

`assets/maps/tenyo/forest-occlusion.json` に描画専用の領域ポリゴンと根元の奥行き `sourceFootY` を明記する。原画で重なった枝葉の画素を複製しないよう、手前のまとまりから画素の所属を確定する。社のシルエット内にある木々は `trees-back` へ分け、必ず社の下に置く。

`python scripts/split-tenyo-layers.py`（Pillow）で全画像を同じ1536×1024 RGBA・原点のまま出力する。リサイズ、移動、描き足し、色変更は行わない。8つの森＋社の背後＋残る前景の全パーツを足したRGBAバイト列が原画と厳密一致することを検査する。

|まとまり|原画での根元の手前端Y|
|---|---:|
|上端・中央左|144|
|北東|176|
|北西|192|
|東・上段|224|
|東・側面|288|
|西・上段|304|
|西・側面|512|
|東・中段|512|

上記は**視覚的な奥行きのみ**。通行不可セルを画像や根元から生成しない。既定の447歩行マス、鳥居の接地行19/20、NPC・宝箱・社の座標、カメラ・縮尺は変更しない。

## 描画順

背景 → 鳥居の付け根 → 社の背後の木々 → 社 → 人物・鳥居上部・周辺8つの森の足元順 → 南側に残る森 → DEBUGグリッド。

森の描画奥行きは `sourceFootY × .75`。人物は移動中の補間された描画足元で比較する。人物が根元より奥なら森が覆い、根元と同じ位置または手前なら人物を上に描く。森同士の同順位も安定させ、人物との同順位では森を先に描く。鳥居上部の奥行きは既定のworld y=504。付け根は引き続きすべての木々より下。

本編に埋め込む森の名前・根元とJSONをQAで照合する。歩行編集ページも同じ分割画像を使う。人物のいない再合成は元の見え方と一致し、最近傍サンプリングで端数カメラ位置の分割境界も一致させる。

## 読込と検証

14画像の読み込み完了をエリア移動が待つ。保存復帰時も画像イベントで再描画し、失敗時は移動取消／再読込メッセージを維持する。

- 画像：RGBAの完全再合成、実alphaの重複・欠落なし、5つのカメラ位置で継ぎ目なし。
- 奥行き：8つのまとまりすべてで根元の0.1world奥／同位置／0.1world手前の実画素を検査。元の写真位置の頭が見えること、南側の森が人物を覆うことも検査。
- 行動：短押し／長押し、447マス連結・1788移動、出入口・NPC・宝箱への到達、画像遅延・失敗、版番号を検査。
- 見た目：本編のhero/shadow関数と採用済み青髪256pxアトラスをnative canvasで描く。本編の社と同じ58pxの見かけの高さ・足元オフセットを使用し、確認ページも同じ。

本編の人物・カメラ・通行判定を変更しない。改善ブランチでPages公開後、周囲を歩いた実機の見え方を確認してからmainへマージする。
