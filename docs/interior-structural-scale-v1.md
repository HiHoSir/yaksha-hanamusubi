# 内観の構造化・縮尺統一計画 v1

2026-10-15 / 対象: 鬼灯の里の茶屋・宿屋・よろず屋・民家

## 到達目標

承認済みのコンセプト絵は**意匠と配置の参照**として維持し、ゲーム内では村と同一のキャラクター足元基準・投影・移動格子に合う「実際に歩ける建築構造」として再構築する。絵を一律に拡大縮小するだけでは解決しない。既存画像、セーブ、イベント、村への出入口を保持し、施設単位で置換する。

## 確認済みの実装上の前提

- `AGENTS.md` および `skills/interior-occlusion-layers/SKILL.md` を優先する。
- `js/interior-base.js` は1536×1024の原画を画面領域 `(0,128)-(768,640)` に対応づけ、現状は4施設とも一枚絵を床面として描画する。これは**画像座標**であり、実際の室内奥行きや家具寸法の根拠にしてはいけない。
- `js/settlement.js` では建物・樹木・NPCは足元を基準に世界座標へ配置される。内部も足元位置・前後順を共通にする。
- 兵具屋カウンターのみ独立前景と接地 footprint の試行済み。他3施設には同等の仕組みが未適用。
- 既存の `layouts.solids` は一枚絵に合わせた暫定の矩形であり、構造確定後に足元 footprint から生成・検査する。

## 新しいシーンデータ規約

施設ごとに下記を別々に保持する。すべて**同一の室内ワールド座標系**で管理し、描画座標への変換は共通関数1箇所で行う。

1. **base**: 壁・床・土間・上がり框・奥行きのある通行面・扉開口。歩ける面の領域と高さ段差もデータ化する。元のコンセプト画像は参照専用として残す。
2. **ground detail**: 床板の継ぎ目・畳縁・踏み石・設置影。これだけでは通行を塞がない。
3. **object**: 卓・布団・帳場・かまど・柱・掛け軸など独立した視覚シルエット。透過画像または同じ描画基準によるポリゴン。位置合わせのための原点／オフセット必須。
4. **footprint**: objectと独立した床面接地範囲。障害物は足元だけ判定し、人物の半径を多重適用しない。
5. **depth anchor / segments**: 人物の補間済み描画足元との比較で前後を決める。長い壁・複雑なL字家具は分割。奥側の人物を家具が隠し、手前側では人物が前に出る。
6. **interaction**: 帳場接客・宿泊・会話・出入口の判定点。footprintとは独立。
7. **navigation**: 32pxの既存移動格子に沿った通路、到達可能領域、床レベル遷移。移動開始前に全行程を判定し、障害物で半歩停止させない。

データ形の例（数値は説明用の仮値であり、画像から測定した確定値ではない）:

```js
{
  id: 'tea-table-1',
  layer: 'object',
  image: 'assets/interiors/structured-v1/teahouse/table-1.webp',
  x: 200, y: 420, scale: 1,
  sourceOrigin: [0, 0],
  depthAnchor: 424,
  footprint: {type: 'polygon', points: [[180,414],[220,414],[220,430],[180,430]]},
  collision: true
}
```

## 縮尺合わせの手順（全施設共通）

- 村内で採用している**緋月と成人NPCの足元から頭頂までの表示高さ**を基準にする。頭身や画像自体を建物ごとに変更しない。
- 同じキャラクターを戸口・部屋中央・家具の奥・家具の手前に配置し、扉の通過幅、卓と座布団、寝具、帳場上端、柱の高さを比較する。
- 奥行きによる縮小・湾曲や中央収束が村と異なる専用効果になっていないか確認する。必要なら投影のほうを共通化し、絵の遠近だけに依存しない。
- 室内の家具の大きさは **NPCとの相対比で決定**し、コンセプト絵に含まれる極端な遠近は再現しない。
- 床面の通行可能範囲は見た目から憶測せず、実装データで可視化して確定する。出入口⇔店員／宿泊イベント／各卓の周囲への導線を確保する。

## 施設ごとの構造要件

### 茶屋
入口付近のみ土間。平たい踏み石を介して上がり框から板の間へ。窓・調理設備・カウンターなし。板の間には4卓。**卓ごとに別オブジェクト・別footprint・個別深度**とし、座布団など接地判定が不要なものを歩行阻害しないようにする。通路が卓で分断されないこと。

### 宿屋
入口土間、踏み石と上がり框、帳場、独立した畳客室2室（各2組の布団）、山水・梅の掛け軸。壁・襖・柱・帳場を別レイヤー化。布団や掛け軸の視覚矩形全体を衝突範囲にしない。帳場裏の店員動線、客室への導線を確保する。

### よろず屋（既存armory）
元絵と既存カウンターの輪郭・フットプリント試作を保存。接客用土間、壁面武具、帳場裏の店員用板床と側面アクセス。最初にカウンターの前後で緋月と店員の縮尺を確定し、その後に壁際物品と柱を個別化する。

### 民家
左側の板の間は奥から手前まで連続し、右側のおよそ半分は土間。畳なし。家具とかまどは独立した接地足元のみのfootprintを持つ。

## 実装順と検査条件

1. **基準値を採取**: 実ゲームの村内NPC・操作キャラの描画高さ、足元位置、室内の現状画像の扉・卓・柱などの画像座標を記録。未計測の寸法を「確定」と扱わない。
2. **茶屋の構造化パイロット**: 原画は残し、床・壁・框・踏み石と最初の卓1個を、寸法が揃う独立レイヤー／独立footprintへ置換。残りの絵は読込中のフォールバックとして残す。
3. **目視と自動QA**: 卓の奥・手前・左右・移動中の重なり、緋月・NPCの相対縮尺、接地辺での遮蔽、32px全歩幅停止と迂回、扉往復と会話を確認する。再合成時のシーム・ハロー・二重影・画像ずれを検査。
4. 合格した卓の設定方法を残り3卓へ展開。次に宿屋→よろず屋→民家の順で導入。既存の`qa/interior-base.cjs`の扉・宿泊・買物チェックを退行させない。
5. Chromiumによる自動テスト、Pages反映、iPhone Safari実機視認は**個別に報告**する。iPhone未実測なら合格扱いにしない。

**現段階**: 本書は実装方針の確定資料。新規の床画像・家具画像・ゲームコード差替えやSafari検査を完了したことを意味しない。
