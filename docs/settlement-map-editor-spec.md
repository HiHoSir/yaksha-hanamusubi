# 里マップエディタ仕様
承認元：本会話の「続けて」。既存 interior-layout-editor.html の発展系を、既存ページを残して別ページとして制作する。

## 目的と出力
- 24種類の透過素材をマス目に配置し、完成図を一枚の背景PNGへ合成する。
- 編集用JSON（素材配置・地形・出入口・出現点）と、同じ明示占有セルに基づく歩行判定JSONを保存できる。
- 本編の村データ・移動処理・セーブへの統合は今回行わない。先に制作ツールで配置と素材品質を検査するための隔離であり、ゲームへの統合完了とは報告しない。

## 基本仕様
- 新規ページ settlement-map-editor.html。既存 interior-layout-editor.html は変更しない。
- 初期17列×15行、1マス32px。編集・書き出しの原点は(0,0)。前回の一枚絵検査用の10px余白を新規地図に流用しない。
- マップの縦横サイズ変更を許可する。初版は各4〜96マス。縮小で配置が消える場合は拒否し、対象を先に移動・削除させる。
- 24素材は既存 hozuki-mapchips-v1/chips_32px/ を再利用。再生成しない。草地・土道・川は自動接続未検証の地形断片として明示し、完成した反復床とは扱わない。フィールド用既存タイルを混ぜない。
- 編集用レイヤーは背景画像（任意）、地形装飾、建物・小物、判定・入口・出現点。検査色・グリッド・キャラは背景PNGに焼き込まない。
- 既存PNGを背景として読み込み可能。地図外は切り抜くが、縦横比を勝手に歪めない。

## 配置と判定
- 素材を選びタップでセルにスナップ配置。選択物の移動、削除、複製、Undo/Redo、ズームを備える。スマホは配置と画面移動をモード分けする。
- 絵の表示サイズと occupiedTiles を分離する。画像bounds/alphaから衝突セルを生成しない。各テンプレートに整数セル列を直接記録し、配置後も占有セルを編集できる。
- 木や建物の裏に入らない設計を基本に、テンプレートの意図した占有セルを明示する。視覚サイズや横幅から占有を丸めない。
- 小物は基本1マス、木は高さ2マス、建物は3マス以上の奇数幅を基本。左右対称の建物の入口は中央列のセル中心。非対称の店は入口セルを個別指定する。
- 地形の手動通行不可セルと物体の明示占有を統合して、配置・経路探索・歩行の共通判定にする。橋は見た目だけで水上歩行を許可せず、terrainPassages に整数の通行セルを明示設定する。terrainPassages は terrainBlocks のみを解除し、物体の occupiedTiles は解除しない。
- 出入口は建物内に無理に歩かせず、隣接する接近セルを到達目標とする。入口マーカーと接近セルを区別する。
- 判定検査は整数、範囲外、占有重複、出現点、各入口接近セルへの4方向到達、1セル幅の通路を対象にする。連結検査合格を画の接地・継ぎ目検査合格と混同しない。

## 歩行と保存
- 現行SD緋月の12フレームを使用。方向ごとのunion boundsにより可視全体を28px以内でセル中央に収める。
- 上下左右のセル単位移動、到着判定に合格した一歩だけを開始。表示は中心間を補間。タップ経路と方向キー・画面十字キーを同じ判定で処理する。
- 編集を変更したら試し歩き状態を止め、無効になった現在位置のまま継続しない。
- 専用localStorageキー yaksha.settlementEditor.v1 を使用。本編・室内エディタのキーへ書かない。保存失敗は通知し、JSONバックアップへ誘導する。
- バージョン付きJSONの入出力。未知素材・不正サイズ・範囲外セル・不正背景画像を読み込み時に検査し、現在の地図は検証完了まで置き換えない。

## 公開と境界
- 最新mainから improve/settlement-map-editor を分岐し、mainへの統合は承認待ち。
- バイナリ・ソース・自動テスト・GitHub登録・Pages・実ブラウザ・iPhone Safariを別々に記録する。
- Pagesは既存の隔離プレビュー方式を使う。公開操作がツールでできない場合は正確な阻害条件を報告し、未公開URLで実機QAを依頼しない。
