# 花見茶屋・描画方針（レイヤー分離不採用）

## 決定（2026-10-23）
ユーザー判断により、精度が不十分な画像の切り抜き・背景修復・前景再合成方式は**不採用**。座卓4台・暖簾の切り出し計画は撤回する。今後の目標は、承認された背景1枚を保持し、キャラクターと床接地判定のみ独立管理すること。

## 現行コードの実行経路（重要）
- `js/game.js` の `S.area === 'teahouse'` 分岐が、一般室内分岐 `YK_INTERIOR_BASE.area(S)` より先に実行される。
- その分岐は `YK_INDOOR_NATIVE_DEBUG.render(...)` を呼び、`js/interior-native-debug.js` の**試作用タイル・柱・家具描画**を使う。したがって、現在の花見茶屋の表示を `assets/interiors/base-v1/teahouse.webp` 1枚だと断定してはならない。
- `YK_INTERIOR_BASE` の花見茶屋画像・当たり判定定義、`TEA_ART` / `drawPaintedTeaActors` / `paintedTeaReady` はコードに残っているが、上記の先行分岐により通常の花見茶屋表示では到達しない。
- 武具屋のカウンター分離処理は別の既存機能。今回の不採用判断だけを理由に削除しない。

## 次の実装条件
1. 既存の花見茶屋の見た目と、ユーザー承認済みの新デザインのどちらを背景正本にするか確認する。画像の画角・寸法・座標を実測する。
2. 正本の1枚絵を描画する単一経路に切り替え、キャラクターの足元・32pxグリッドの当たり判定・NPC・出入口を一致させる。画像の前景切り出しは行わない。
3. `YK_INDOOR_NATIVE_DEBUG` からの移行時に、デバッグ機能を本番コードから分離し、セーブと既存の入口・出口の動作を回帰検査する。
4. 変更は改善ブランチのみ。ソーステスト、隔離Pages公開、iPhone Safari確認、ユーザー承認の順で検証し、その後にmainへマージする。

## 状態
分離方式の撤回と実行経路のソース確認は完了。ゲーム描画の差し替え、アセット変更、Pages検査は未実施。
