# 共通マップ制作規約：トップビューとSDマス目移動

2026-10-23 採用。屋内・村・フィールドなど、今後新規作成または再制作する探索マップの共通基準とする。他チャットでも本書と `AGENTS.md` を実際に読む。

## 適用と優先順位

- 新規・再制作では本書を、従来の「室内58px」「足元をマス中央」「斜め遠近投影に合わせる」「旧base-v1内装画を維持」「建築は常に3分割」の既定値より優先する。外見・役割・世界観の承認内容は引き継ぐ。
- この規約の登録だけで、既存マップ・セーブ・戦闘・イベントを自動移行しない。対象マップを調査し、改善ブランチで実装・検査してから承認を得て統合する。
- 茶店の採用基準画像：`design-reference/maps/topview-v1/cyamise-approved.png`。見下ろし角・配色・ドットの密度の参考とする。これは検査用画像であり、床の補修境界や切り抜き輪郭まで完成品質と認定したものではない。
- 緋月の実画像：`assets/characters/hizuki/field-sd-v1/walk-atlas-32.png`。水色ボブ・金角・衣装などの外見は `docs/characters/HIZUKI_CANON.md` を参照する。外見正本のHD画像と、マップ用SDアトラスを区別する。

## 1. 制作前に固定する仕様

次の項目を対象マップの仕様として記録する。茶店固有の座標・部屋寸法・画像切り抜き数値を他マップへ流用しない。

| 項目 | 必須内容 |
| --- | --- |
| 対象 | マップID、新規／再制作／歩行判定のみ変更の別、承認済みの配置 |
| 地面 | `tileSize: 32`、整数の列数・行数、地形・高さ・出入口 |
| 表示 | `camera: topdown-orthographic`、共通の描画原点、表示倍率、画像の役割と出力先 |
| キャラ | 実アトラス、方向・フレーム構成、可視部分を収める範囲、`visible-center` 配置 |
| 物体 | ID、描画位置、意図した大きさ、明示した整数セル列 `occupiedTiles`、描画レイヤー |
| 通路 | 出現セル、出入口、NPCに話しかけるセル、奥の家具前など必須の接近セル |
| 変更範囲 | 位置・寸法・個数・部屋サイズを維持する項目、今回変更してよい項目 |

地面の接続規則・地形高さ・坂・既存のイベント条件は別データとして維持する。地形を変更する作業では terrain-elevation と既存の移動規則も読む。

## 2. 視点と画風

- 床は正方形のマスを同じ大きさで並べる。左右の壁は平行・垂直、奥と手前の縁は水平とする。消失点、奥ほど狭くなる床、台形の部屋、アイソメの斜め軸を入れない。
- 壁は上面・厚みを主に示す低い帯状にする。奥壁の大きな正面絵や長い柱で画面を占めない。家具は天板・座面、茶釜は蓋を上から見せ、前面の縁は小さくする。
- 1990年代SFC和風RPGに合うピクセルアートとする。輪郭・木目・陰影を意図したドットの塊で構成し、少数段階の色で材質を表す。高解像度の滑らかな絵を縮小・減色しただけで「ドット絵が完成した」と扱わない。
- 背景とキャラクターのドット密度を実表示で揃える。全方向の壁と床の外周を画面内に収め、上下左右の欠けを確認する。
- 透過が必要な独立物体は実RGBAとし、余白・接地位置・切り抜きオフセットを記録する。完成用画像にマス目・文字・検査色を焼き込まない。

## 3. 生成方法

1. `AGENTS.md`、asset-design、カテゴリ別ルール、本書、実際の承認画像と描画処理を読む。
2. 既存の採用済み素材を調べる。配置・縮尺・透過・合成の修正で済む場合は新規生成しない。視点そのものの描き直しが必要な場合は、その理由を記録する。
3. 上記仕様を確定し、`.agents/skills/asset-design/templates/topview-map-prompt.md` を基に1つの制約付きプロンプトを組む。マップID・部屋の種類・家具や建物の種類・セル数・通路を対象の仕様に置き換える。
4. 主参照は実SDキャラと承認済みトップビューとする。旧パース絵を使う場合は配色・持ち物などの参照用途だけを指定する。旧構図を強い主参照にすると、正面壁の大きい絵へ戻るので注意する。
5. 1回の主生成で候補を作り、カメラ・外周・構成・キャラ比率を確認する。側壁だけ平行でも、奥壁の正面感が強ければトップビュー合格とはしない。
6. 生成画像のピクセル寸法やマス位置を信用せず、実際の32pxグリッドに合わせて素材化する。画像の見た目から通行不可セルを丸めて作らない。仕様に合わせて絵を整える。
7. 不備があれば、構図・寸法・原点・レイヤーの問題を切り分ける。再生成の前に修正・再利用の可否を判断する。説明なしの連続生成をしない。

一枚の部屋絵はまず構成資料として扱う。ゲーム用タイル・独立素材・一枚背景のどれを使うかは、下記のレイヤー条件と実検査で決める。新規の床タイルには通常の継ぎ目・反復検査も行う。

## 4. キャラクター全体を1マスに収める

- 論理移動は32×32pxのマス単位・上下左右4方向とする。停止セルは整数座標で管理する。
- 緋月の可視グラフィックは原則28px高とし、32pxセルの中央に**可視部分全体**を置く。足元をセル中央に置かない。28px高なら上下に約2pxずつ余裕ができる。
- 透明な32px画像枠と可視シルエットを区別する。方向ごとに全歩行フレームのアルファ範囲を合わせたunion boundsを一度求め、同じ方向の全フレームで同じ変換を使う。毎フレーム測り直して再中央寄せし、足や頭を揺らさない。
- 新規NPCも同じ「可視全体をセル内」の基準で制作する。承認された体格差は維持する。単に旧HD絵を縮小しただけでSDの新作と呼ばない。
- 縦横比を保ち、全フレームがセル内に収まることを実アルファで検査する。大きな登場人物を必要とする場合は、制作前に複数セルの規格を定義する。

可視boundsを `b`、全レイヤー共通の描画原点を `origin` とした例：

```js
const cx = origin.x + (tx + 0.5) * 32;
const cy = origin.y + (ty + 0.5) * 32;
const scale = Math.min(28 / b.width, 28 / b.height);
const dx = cx - (b.left + b.width / 2) * scale;
const dy = cy - (b.top + b.height / 2) * scale;
// dx,dyから元の32pxフレーム全体を縦横同倍率で描く。
// cx,cyは移動の基準。可視の足元はcy + b.height * scale / 2。
```

boundsは表示専用とする。アルファや画像矩形からキャラ・物体の衝突セルを導出しない。28pxはカメラ拡大前の論理サイズであり、画面上の28px固定ではない。全マップで同じSD基準を使い、エリア名によってHD版へ切り替える分岐を追加しない。地図全体の倍率・スクロールはキャラ・床・物体へ共通に適用する。

## 5. 移動・配置・当たり判定

- 壁・家具・建物などの占有は `occupiedTiles: [[tx,ty], ...]` の整数セル列で直接指定する。画像幅、影、PNG端、接地ピクセルから自動変換しない。
- 上下左右の一歩が始まる前に到着セルを検査する。通行不可なら一歩全体を開始せず、途中で止めない。歩行判定・タップ移動の経路探索・配置検査は同じ占有データを使う。
- 移動中は出発セル中心から到着セル中心へ表示を補間する。停止時のセル内収容と、移動中に2セル間を通ることを区別する。
- 頭がはみ出すことを避けるための余分な通行不可マスを足さない。キャラはセル内に収め、空いている床は歩行可能にする。奥の家具の**手前の床**は、接近・会話・調査に必要な通路として指定・検査する。
- 左右対称が承認されたマップでは、セルの中央軸で占有を反転して照合する。画像の中央ピクセルから判定軸を推測しない。意図した非対称の地形は勝手に対称化しない。
- **歩行範囲だけの依頼では、家具・椅子を動かさず、部屋を広げず、床の行を足さない。** 承認済みの配置・部屋寸法・画像を固定し、不要な判定を直す。広げられる空き床がなければ、その事実と対象セルを報告し、別の間取りへ勝手に変更しない。

家具の規格は対象ごとに制作前に決める。採用済みトップビュー茶店は卓2×2マス、腰掛け2×1マス。これを全マップの全家具へ一律適用しない。旧斜め茶屋の卓2×1マスは新トップビューの固定規格ではない。

## 6. 少ないレイヤーで成立させる

- 歩ける地面・低い装飾は常に背景。物体の見た目を宣言した占有セル内へできるだけ収め、歩ける隣セルを隠さない。
- キャラも物体もセル内で完結し、遮蔽が要らない場面は「背景＋キャラ」で構成できる。すべての家具に前景画像や3分割壁を作ることを義務化しない。
- 木冠・屋根・高い柱などが通行可能セルへ張り出す場合だけ、必要な範囲を独立した前景または深度単位に分ける。床の影は背景に残す。
- 前後関係が変わる物体だけを、移動補間中の可視の足元と同じ描画順で扱う。画像枠や移動先セルだけで並べ替えない。
- 1枚の画像の中で「常に後景」と「状況次第で前景」を混在させない。生成後の大雑把な矩形切り抜き・実行時アルファ修正を完成素材の代用にしない。

## 7. 検査・公開・引き継ぎ

1. 実SDキャラを重ね、グリッド・通行不可セル・セル中心・可視の足元を別表示する。完成画に重ねた検査色は解除できるようにする。
2. 全方向・全フレームのアルファが停止セル内に収まることを確認する。方向切替・足元の揺れ・画像読み込み前後の旧素材の一瞬表示も確認する。
3. 占有の整数／範囲／重複、壁・家具への進入防止、全必要地点への経路、奥の家具前の通路、出入口・NPC会話・段差を検査する。判定だけの変更では配置・部屋サイズが変わっていないことも比較する。
4. タップと十字キー、長押し、連続歩行、移動中の前後順を確認する。セーブ・ロード・入口遷移も対象に応じて確認する。
5. binaryは既存の github-image-atlas と github-artifact-delivery の手順でGitHubへ登録し、実バイトと参照パスを検証する。
6. 改善ブランチ・本編統合の承認・BETA/cache更新は `docs/improvement-branch-workflow.md` と `AGENTS.md` に従う。iPhone検査を依頼する前に、既存のPages公開方式で対象コミットを公開し、URLの画像とJSが最新版と一致することを確認する。
7. デザイン承認、素材仕上げ、ローカル検査、GitHub登録、Actions、Pages、ブラウザ、実機Safariを別々に報告する。「良さそう」というデザイン承認を、未実施のSafari操作検査の合格へ読み替えない。

茶店の実装例は改善ブランチの `js/cyamise-walk-rules.js`、`js/cyamise-walk-renderer.js`、`qa/cyamise-sprite-cell.cjs`、`qa/cyamise-topview.cjs` を参照できる。例の固定キャンバスや補修座標を共通エンジンの既定値にしない。既存描画の実コードを調査して適用する。

別チャットへの依頼例：

> AGENTS.md、docs/topview-map-standard.md、asset-designスキルに従い、対象マップをトップビュー・SDのマス目移動で制作してください。指定した承認済み配置は維持し、生成前に占有セルと必須通路を確定してください。
