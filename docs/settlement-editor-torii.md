# 里マップエディタ：既存鳥居の再利用と接地判定

## 対象
- 既存の採用素材 `assets/terrain/places-v1/torii.png`（64×64 RGBA）を**無加工で再利用**し、パレットへ `torii_gate`（鳥居）として登録。
- 1マス32pxのエディタでは、表示上だけ128×128px（横4マス相当）に最近傍で拡大。**表示高さは衝突判定に影響させない**。
- 配置座標 `[x,y]` は最下段の左端セル。画像の下辺をその行の下辺に合わせる。
- `displayCells:[4,4]` / `renderCells:[4,4]` は表示・マップ境界検査用。これが全16セルを占有する意味ではない。

## 明示した接地セル
```
表示の上部      通行可   通行可   通行可   通行可
                通行可   通行可   通行可   通行可
                通行可   通行可   通行可   通行可
接地の最下段    通行不可 通行可   通行可   通行不可
                 左柱      通路     通路      右柱
```

`occupiedTiles: [[0,0],[3,0]]`。ほかの14セルは鳥居自身の判定ではブロックしない。**上段や上部の描画には接地制限を設けない**。地形判定や別物体、手動通行不可があるセルについては、それらの既存ルールが優先される。

## 実装
- `js/settlement-map/catalog.js` — 画像パスと横4マス、両柱の占有を登録。
- `js/settlement-map/model.js` — `renderCells` が明示された素材のみ、元画像の切り抜きサイズとは別に実表示矩形を設定する。旧素材の計算経路は変更しない。
- `js/settlement-map/render.js` — 既存のobject描画と `imageSmoothingEnabled=false` をそのまま使用。新規画像生成もPNG差し替えも行わない。
- JSONの形式と `catalogRevision:4` は維持。追加登録のため旧マップの自動移行は不要。

## 品質確認
- 画像：64×64実画像がGitHubに存在すること。
- 位置：左下 `[x,y]` の4セル幅の画像描画、右端は `x+3`。
- 判定：`[x,y]`、`[x+3,y]` のみ鳥居由来の通行不可。 `[x+1,y]` と `[x+2,y]` を経路探索が通れること。
- 保存：エディタJSONの書き出し→再読み込み後、接地の2マスを維持。
- 既存素材：井戸・茶屋など `renderCells` を指定しない物体の描画位置は変わらない。
- 本編・Pages・iPhone Safariは別検査とし、改善ブランチの登録だけで実機確認済みと報告しない。
