# True Pixel 32 — 32pxグラフィック汎用制作

## 最初に必ず読む
1. リポジトリの `AGENTS.md`、`.agents/skills/asset-design/SKILL.md`、`references/low-resolution-graphics.md`、対象カテゴリの規約を実際に取得。
2. **本スキルの根拠・詳細**：[`docs/graphics/true-pixel-32-workflow.md`](../../../docs/graphics/true-pixel-32-workflow.md)。
3. NPC／キャラは承認済み緋月32pxアトラス、タイル・物体は `create-grid-map-art` と `field-mapchip-art` 等の規約。GitHub反映は `github-artifact-delivery` / `github-image-atlas`。
4. 実画像・実装ファイル・制作対象ブランチを確認できなければ推測して作業しない。

## 適用先と優先順位
汎用対象：実32pxキャラクター／NPC、地面・接続タイル、装飾・家具・建物。カテゴリの固有規格は本スキルより優先する。
**キャラの静止／歩行固定規則をタイルに流用しない。タイルのseamless規則を人物に流用しない。**
生成前には `asset-design` の生成前手順とカテゴリ別テンプレートが必須。既存素材の編集・変換で足りるなら画像生成しない。

## 必須手順
1. **契約**：原画の出自・承認版、1セル32×32、必要セル数、視点、接地・占有／接続、描画時の目標不透明高さ、固定色／保護画素・領域、出力パスを明記。
2. **原画を簡素に**：輪郭と色面を優先。過剰なハイライト、髪筋、顔の影、素材内のランダムテクスチャを入れない。小サイズで意味があるアクセントだけに限る。無条件の彩度・コントラスト・輪郭強調は初期OFFまたは中立値。
3. **真の32pxに変換**：透明外接矩形・縦横比・サンプリング・色数を点検。高解像度ドット絵風はまだ候補。実寸と整数倍拡大を両方表示して確認。
4. **基準1コマ／1チップを承認**：顔、肌、特徴色、接地・接続部分を確定し正本を別名保存。量産は承認後。
5. **色・部位を保護して展開**：固定肌色は変更不可。キャラは方向間のサイズ・足元と、静止→歩行A/Bの頭部画素一致を確認。タイルは4辺／角の接続と3×3敷き詰め。物体は当たり判定・接地・遮蔽を別に検査。
6. **差分検査**：元画素から変更された座標・RGBAを取得し、保護領域の差分ゼロを保証。意図しない頭のちらつき、孤立画素、透明余白の変化を検査。
7. **実表示比較**：ファイル32pxと画面表示28pxなどを混同しない。不透明シルエット×倍率×カメラを計測し、緋月や既存タイルと並べて評価。必要ならコード側の倍率を直し、採用済み肌／顔を再加工しない。
8. **反映・報告**：GitHub実PNG・参照経路・ビルド版整合を確認。Actions、Pages、Safariを別々の合否として報告し、未実施を「成功」と書かない。

## 停止・やり直し条件
- 正本の顔や肌が変わる／サンプリングで造形が破綻する：**原画再生成に戻らず**既存画素から局所的に復元。
- 32pxセル分割、アトラス行列、方向マッピングが曖昧：書き出し／実装を停止して現物を検査。
- タイル接続や物体接地が未確認：採用・完成扱いにしない。
- 表示サイズの問題：画像生成ではなく、まず描画倍率・不透明領域・足元を調査。

## 最終チェック
- [ ] 現行規約と承認済み原画を確認
- [ ] 元画像は明暗控えめ・色面主体
- [ ] 真の32px、透明、色数、セル配置を検査
- [ ] 保護RGBA／座標の意図しない変更ゼロ
- [ ] カテゴリ別の歩行／3×3接続／接地・遮蔽を検査
- [ ] 実描画で緋月・周辺地形とのサイズが合う
- [ ] PNG・JSON・実装参照の整合と、CI/Pages/Safariの個別報告

白妙の成功・失敗と根拠は上記 `docs/graphics/true-pixel-32-workflow.md` を参照。
