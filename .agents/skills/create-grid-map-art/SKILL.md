# トップビューマップとマップチップ制作

絵・セル座標・接地・通行判定を別データとして設計し、同じ実キャラ・レンダラーで検査する。既存の採用画像を見つけ、再利用可能なものを先に使う。

## 読み分け

- 設計・生成・透過チップ化： [制作手順と素材契約](references/art-workflow.md)。
- 道・川・橋・柵などの連結素材： [オートタイル](references/autotiles.md)。
- 『新生 鬼哭の花契り』：必ず [プロジェクト接続](references/yaksha-project.md) を先に読み、対象ブランチの現行仕様を取得する。過去の検査記録より現行カタログ・モデルを確認する。

## 制作順序

1. **現物確認**：対象・作業ブランチ・承認画像・実SDキャラ・描画処理・既存素材を確認する。スクリーンショットの切り抜きを村全体の規模や配置指定と解釈しない。
2. **用途確定**：イメージ図、一枚背景マップ、個別チップのどれを納品するか記録する。構想図の再配置を頼まれていないのに、採用画像を別構成の地形や簡略図へ置換しない。
3. **契約作成**：対象マップの列×行、32px基準、視点・参照の役割、各素材の表示セル数・接地アンカー・明示占有・入口・接近セル・レイヤー・透過・出力先を記録する。サイズ変更の可否と既存配置の維持範囲も記す。
4. **経路を先に確保**：必要動線を上下左右に最低1セル幅でつなぐ。入口はセル中央、対称建物の中央入口は奇数幅3セル以上を使う。井戸は1セル、小物は基本1セル、木などの高さ表現は2セルを目安にする。建物は小さめの複数セルを許し、種類・規模で決める。村の外にも空き地・草・岸などを描き、画面端で建物や地形を不自然に切らない。
5. **原画と規格化**：不足する絵のみ制約付きで生成する。透明原画を検査し、縦横比保持・余白管理・最近傍拡縮・必要な減色で規格化する。縮小・減色だけでドット絵品質が完成したとは扱わない。正確な接続形状は規則で構築する。
6. **実装・検査**：独立IDとメタデータを登録し、実SDとの等倍合成、マス目・判定の切替、全入口と必要地点への経路、4方向歩行・前後順・保存往復を検査する。PNGのアルファから判定を推測しない。
7. **保存・引継ぎ**：採用原画または再構築用source、最終PNG、プロンプトと参照、配置JSON、検査用画像、再構築手順を保存する。GitHub登録・公開・ブラウザ・実機検査は別段階で報告する。

## 描画方式を混同しない

| 方式 | 成立条件・納品 |
| --- | --- |
| 一枚絵を背景として直接使う | 実グリッドに合い、歩行中の前後関係が変化しない配置。背景PNG＋同じセル座標の判定／入口データ。建物裏へ回る表現を避ける。検査を通せばその絵自体を採用できる |
| チップで組み立てる | 地面＋独立RGBAチップ＋配置JSON。接地基準と深度順を共有し、接地以外の表示重なりは許す。合成PNGだけでは動的遮蔽は再現されない |

キャラは可視全体を原則28px以内にして32pxセル中央へ置く。物体は可視下辺を接地セル下辺へ合わせる。キャラを物体と同じ下辺合わせに変更しない。

## 典型的な失敗への対処

- 大きすぎる建物：実キャラで比較し、表示セル数を見直す。小物の1セル規則を建物全体に適用しない。
- 古い説明の「木冠は通行可」を一枚背景に適用：用途を確認し、背後経路を閉じるか独立チップ化する。
- 店が大きい／入口がずれる：小型共通建物と看板差分を使い、入口列と占有を先に固定する。
- 椅子を動かして歩行範囲を修正：判定のみ依頼なら画像・配置を保ち、空いている手前セルの不要な判定を直す。
- プレビューを完成マップと報告：素材検査図・設計案・採用マップ・公開状態をそれぞれ明記する。
